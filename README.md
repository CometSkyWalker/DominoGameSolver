# Перекрывающиеся доминошки

На квадратное поле по очереди кладут цветные доминошки: каждая занимает две
соседние клетки, вдоль или поперёк, класть можно внахлёст. Кто лёг позже — того и
видно; клетка, до которой никто не дотянулся, остаётся пустой.

Дана только готовая картинка. Нужно восстановить порядок ходов (или объяснить, что
его нет) и посчитать, сколько разных картинок вообще можно сложить. В условии четыре
вопроса — сделаны все четыре, плюс окно, консольная версия и проверки.

![интерфейс](demo.png)

## Запуск

Проще всего — двойным кликом:

- **`start_cli.bat`** — консольная версия. После ответа окно ждёт Enter, поэтому
  результат успеваешь прочитать;
- **`start_gui.bat`** — окно. Консоль при этом не появляется.

Из терминала:

```bash
python main.py                  # консольная версия, зависимостей нет
python tests/test_solver.py     # 33 проверки
python tests/stress_test.py     # жёсткие стресс-тесты на больших данных

pip install -r requirements.txt
python main.py --gui            # окно (нужны customtkinter и pillow)
```

Питон от 3.8. Если в Linux не находится tkinter — `apt install python3-tk`.

## Четыре режима

| Режим | Дано | Ответ |
|---|---|---|
| 1 | набор доминошек по цветам + картинка | порядок ходов либо объяснение, почему его нет |
| 2 | последовательность цветов + картинка | расстановка строго по этой последовательности |
| 3 | набор доминошек | сколько разных картинок можно получить |
| 4 | последовательность цветов | то же самое |

Поле — таблица чисел: `0` — пустая клетка (её никто не накрывал), иначе — цвет
доминошки, накрывшей клетку последней. Размер доминошки фиксирован условием.

## Как это решается: разбирать с конца

Перебирать «что положили первым» бессмысленно — вариантов столько, что счёт не
кончается. Поэтому разбор идёт с конца.

Доминошка, положенная последней, ничем не закрыта: обе её клетки показывают её цвет,
она видна целиком. Значит её можно снять, а освободившиеся клетки пометить как
разобранные — прежний цвет под ними уже не важен. То же с предпоследней, и так пока
цветных клеток не осталось. **Порядок выкладывания — это порядок разбора наоборот.**

Снять доминошку можно, если под ней нет пустых клеток, все ещё не разобранные клетки
одного цвета и хотя бы одна такая клетка есть.

Почему это верно, в двух наблюдениях:

- **снятие соседям только помогает.** Разобранная клетка подходит под любой цвет, а
  новых цветов и пустот при снятии не появляется — значит снять доминошку никогда не
  мешает снять другую. Отсюда: убирать можно в любом порядке, и если картинка
  собирается — «жадный» разбор уберёт с неё все цветные клетки. Это и есть критерий:
  цветные клетки остались после разбора — картинка не собирается никак;
- **на пустую клетку класть нельзя.** Любая доминошка целиком лежит на цветных
  клетках. Отсюда мгновенный отказ: одинокая цветная клетка, вокруг которой пусто,
  недостижима — вторая половина доминошки легла бы на пустое место.

## Режим 1: ограниченный набор

Мало разобрать картинку — нужно уложиться в выданный набор. Сначала мгновенная
**проверка по количеству**: клетка показывает цвет накрывшей её доминошки, а одна
доминошка отвечает максимум за две клетки, поэтому клеток цвета `c` не бывает больше
`2·a_c`. Не сходится — отказ без единого шага перебора. Условие необходимое, но не
достаточное, поэтому дальше работает разбор.

Жадничать при этом нельзя — можно попасть в тупик. На фигуре ниже (доминошек ровно
две) вертикальная пара посередине раскалывает её на две одиночные клетки:

```
. 1 1
1 1 .
```

Программа доходит до тупика, откатывается и берёт две горизонтальные пары. Просмотренные
положения запоминаются, чтобы не считать одно и то же дважды. Если ни один порядок не
влезает в набор — «картинка собирается, но не из выданного».

У перебора есть бюджет по числу состояний. Если он исчерпан, программа не пишет
«невозможно» (это было бы враньём — невозможность не доказана), а честно отвечает
**«не определено»**: не успела ни собрать, ни доказать, что нельзя.

## Режим 2: порядок задан заранее

Последовательность менять нельзя, класть надо все. Разбор строго задом наперёд:
последняя доминошка убирается первой — перебираются её места, затем предпоследняя, и
так далее. В конце проверяется, что цветных клеток не осталось. Отдельный случай:
доминошку могли полностью закрасить те, что легли позже, — на картинке её нет, при
разборе это место из уже разобранных клеток. Это разрешено.

## Режимы 3 и 4: сколько всего картинок

Хранятся не ходы, а сами картинки — одинаковые сразу схлопываются, поэтому перебор не
разрастается. На поле 2×2 две доминошки дают 16 действий, но только 9 разных картинок.
В режиме 3 рядом с картинкой держится ещё и остаток набора (порядок влияет на
результат, поэтому перебираются и порядки).

На большом поле картинок сотни миллионов — хранить негде. Тогда включается оценка: как
при сборе наклеек, доминошки много раз раскладываются наугад. Если картинки часто
повторяются — их немного и почти все собраны; если почти каждая новая — за кадром ещё
много. Формула — оценка Чао (1984):

```
D + f1·(f1 − 1) / (2·(f2 + 1))
```

где `D` — сколько разных картинок встретилось, `f1` и `f2` — сколько из них попались
ровно один и ровно два раза. Ответ выглядит так: `примерно 400 000 000, но точно не
меньше 39 999`. Второе число честное — эти картинки реально встретились; первое даёт
порядок величины и округлено, чтобы не выглядеть точным. В условии сказано «вычислите
**или оцените**».

## Скорость

Мест для доминошки на поле со стороной `n` — `2·n·(n−1)` (на 8×8 это 112). В режимах 1
и 2 на каждом шаге перебираются все места, шагов не больше числа клеток, но запоминание
просмотренных положений сильно сокращает перебор. Точный подсчёт в режимах 3 и 4 зависит
от числа картинок; как только их слишком много — оценка, а она считается быстро при
любом размере поля.

## Проверки

`test_solver.py` — 33 штуки без сторонних библиотек. Три большие сверки:

- **все картинки подряд.** На 2×2 с двумя цветами всего 81 картинка; перебором
  находится, какие собираются, и результат сверяется с решателем — расхождений нет;
- **обратная проверка.** Каждый найденный порядок раскладывается обратно и сравнивается
  с исходником — так проверяются 200 случайных картинок;
- **сверка подсчёта.** Быстрый счёт сверяется с перебором в лоб на малых полях; отдельно
  проверяется, что на большом поле включается оценка.

Отдельно закрыты каверзные случаи: важный порядок разбора, одинокая клетка, нехватка
доминошек, перекрытия, полностью закрашенная доминошка, тупик с откатом. `stress_test.py`
дополнительно гоняет исчерпывающие сверки и десятки тысяч случаев на больших полях.

## Оговорка

В режиме 1 лишние доминошки разрешено не класть (лишние — те, что не участвуют в итоговом
разложении): их всегда можно положить одну на одну поверх уже закрашенных клеток. В
режимах 2–4 набор и последовательность идут целиком.

## Файлы

```
main.py                точка входа: консоль, с --gui окно
start_cli.bat          запуск консольной версии двойным кликом
start_gui.bat          запуск окна двойным кликом
dominoes/
    model.py           поле, ход, раскладка ходов
    solver.py          все четыре режима
    ui/
        cli.py         консольная версия
        gui.py         окно
        theme.py       цвета и оформление
tests/
    test_solver.py     33 проверки
    stress_test.py     стресс-тесты
```

Решатель (`dominoes/model.py` и `dominoes/solver.py`) написан на голом Python и от
интерфейса не зависит — сторонние библиотеки нужны только окну.
